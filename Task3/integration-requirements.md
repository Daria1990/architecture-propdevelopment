# Требования к внешним интеграциям: сервисы «Умный дом»

**Автор:** Дарья Палюлина
**Дата:** 2026-09-20

## Что интегрируем

Партнёр предоставляет две услуги, которые должны быть доступны собственникам через существующее мобильное приложение:

- **Интеллектуальный домофон** — видеозвонок и открытие двери из приложения; автоматическое открытие по лицу тем, кому разрешён доступ.
- **Интеллектуальный шлагбаум** — открытие из приложения; автоматическое открытие по номеру автомобиля, которому разрешён въезд.

Что уходит партнёру и что приходит от него:

| Направление | Что передаётся | Категория данных (из Task1) |
| --- | --- | --- |
| PropDevelopment → Партнёр | Команда «открыть дверь / шлагбаум» | Секретные (управление замком) |
| PropDevelopment → Партнёр | Список, кому разрешён доступ: идентификатор человека, номер автомобиля, дом, подъезд, срок действия | Конфиденциальные (персональные данные) |
| PropDevelopment → Партнёр | Фото лица для регистрации в системе распознавания (один раз, при добавлении) | Конфиденциальные — биометрические персональные данные |
| Партнёр → PropDevelopment | События: звонок в домофон, открытие, распознавание лица или номера | Конфиденциальные (кто и когда входил) |
| Партнёр → PropDevelopment | Видеопоток звонка в домофон | Конфиденциальные |

## 1. Требования к безопасности

| № | Требование | Зачем |
| --- | --- | --- |
| Б1 | Весь обмен с партнёром — только через API Gateway. | Одна точка контроля. |
| Б2 | Только HTTPS. | Команды и персональные данные не передаются открыто. |
| Б3 | Партнёру — только нужное: идентификатор человека, номер авто, дом, подъезд. Без ФИО, телефона, квартиры. | Минимум данных. Проблема кейса — лишние данные в API. |
| Б4 | Партнёр видит только подключённые дома. Каждый запрос проверяется на принадлежность к дому. | Проблема кейса — партнёр видел чужие данные. |
| Б5 | Фото лиц храним не мы, а партнёр. У нас — только идентификатор и согласие собственника. | Биометрия — особая категория по 152-ФЗ. |
| Б6 | Все команды и изменения доступа пишутся в журнал: кто, что, когда. | Разбор инцидентов. |
| Б7 | Ключи и сертификаты — в хранилище секретов, не в коде. Регулярно меняются. | Секретные данные из Task1. |

## 2. Аутентификация и авторизация

### Собственник → мобильное приложение → smart-home-app

| Что | Как |
| --- | --- |
| Аутентификация | OAuth 2.0 / OpenID Connect через существующий `auth-service-1`. Короткоживущий access-токен (JWT) + refresh-токен. |
| Подтверждение опасных действий | Открытие двери и изменение доступа — с подтверждением биометрией телефона или PIN-кодом. |
| Авторизация | `smart-home-app` по CRM проверяет, что собственник относится к этому дому. Управлять доступом может только собственник, жилец — только пользоваться. |

### PropDevelopment → Партнёр (команды, списки доступа)

| Что | Как |
| --- | --- |
| Аутентификация | OAuth 2.0 Client Credentials + mTLS (взаимная проверка сертификатов). |
| Авторизация | Права только на дома PropDevelopment: открывать устройства, управлять списками доступа. |

### Партнёр → PropDevelopment (события, webhook)

| Что | Как |
| --- | --- |
| Аутентификация | HMAC-подпись каждого события + белый список IP партнёра. Проверяет API Gateway. |
| Авторизация | Партнёр может только присылать события. |

## 3. Как организовано взаимодействие

### Схема

```
Собственник ──(мобильное приложение)──▶ Firewall ──▶ smart-home-app ──▶ API Gateway ──▶ Партнёр «Умный дом»
                                                            ▲                  ▲
                                                     CRM (дом, квартира)   события (webhook)
```

### Сценарии

**Открыть дверь или шлагбаум из приложения**
1. Собственник нажимает «Открыть» и подтверждает биометрией телефона.
2. Приложение отправляет команду в `smart-home-app` с access-токеном.
3. `smart-home-app` проверяет токен, по CRM проверяет, что собственник относится к этому дому.
4. `smart-home-app` через API Gateway отправляет партнёру команду «открыть устройство X».
5. Партнёр открывает и присылает событие «открыто». Собственник видит результат в приложении.
6. Команда и результат записаны в журнал.

**Добавить человека по лицу**
1. Собственник в приложении добавляет жильца, фотографирует лицо и подтверждает согласие на обработку биометрии.
2. `smart-home-app` создаёт запись «жилец разрешён в доме X до даты Y» и один раз передаёт фото партнёру через API Gateway.
3. Партнёр регистрирует лицо и возвращает идентификатор. Фото у нас не сохраняется, хранится только идентификатор.
4. Когда человек подходит к двери, партнёр распознаёт его сам и открывает. Нам приходит событие «вход по лицу, идентификатор N».

### Технические требования к взаимодействию

| № | Требование |
| --- | --- |
| В1 | REST + JSON поверх HTTPS. Контракт описан в OpenAPI, согласован со специалистом по ИБ. |
| В2 | События от партнёра — webhook. При недоступности партнёр повторяет отправку. |
| В3 | Команда открытия идемпотентна: повтор той же команды не открывает дверь второй раз. |
| В4 | Версионирование API: старая версия поддерживается после изменений контракта. |
